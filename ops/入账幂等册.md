# 入账幂等册

- 生效日：2026-11-20（当天锁定，禁止改口）
- 适用仓：`08-windowcut`（业务窗关账）
- 缺陷编号：BUGFIX-05
- 锁定口径：**甲路径 — 查重拒绝**
- 明确排除：乙路径（覆盖 + 抬 generation + 被盖快照）**不得与本册混用**；本仓任何入账写路径不得出现覆盖式“幂等”。

## 1. 同键定义

| 词 | 定义 |
|----|------|
| 同窗 | `windows.name` 相同 |
| 同键 | `events.biz_key` 相同 |
| 正式入账 | `events.window_id = 当前窗` 且 `events.disposition = '窗内'` |
| 重复 | 同窗下已存在同键的正式入账行 |

## 2. 甲路径写路径（唯一正确口径）

1. 入账先占键锁：`ingest-key:<window_name>:<biz_key>`，**独占**（同一持有人并发请求也不得重入）。
2. 再占窗锁：`ingest:<window_name>`。
3. 在同一事务内按“同窗 + 同键 + disposition='窗内'”查重。
4. 命中重复：**整笔拒绝，正式零增**；写审计 `ingest_dup_skip`（目标为 biz_key，载荷含 window_id / 既有 event_id / `path: 甲`）；返回 409。
5. 未命中：写入一行正式事件，写 `ingest_in_window` 审计；返回 200。
6. 跳过/争用均不得写入正式行；不得只改重复提示文案。

## 3. 并发口径

- 两人同时写同窗同键：先到者占键锁；后到者只写 `contention_log`（锁键为 `ingest-key:...`），业务零写，不得落 `ingest_in_window` 审计。
- 后到者不得删除先到者的锁；释放只能释放自己持有的锁。
- 键锁释放后，同键才可重新进入查重流程。

## 4. 五处同态

| 面 | 必须表现 |
|----|----------|
| 事件列表 `/api/events` | 同窗同键最多 1 行正式事件 |
| 审计 `/api/audit` | 重复尝试有 `ingest_dup_skip`；争用无 `ingest_in_window` |
| 窗口详情 `/api/windows/{id}` | 笔数/金额按真实行统计，不因重复请求增加 |
| 对账 `/api/reconcile` | 按真实行计数（禁止 `COUNT(DISTINCT biz_key)` 掩护双影），与事件列表一致 |
| 争用 `/api/contention` | 后到者留争用行，业务零写 |

## 5. 偏离处理

- 任何实现偏离本册（例如改走乙路径、只改文案、用 DISTINCT 掩盖、跳过锁）一律**拒写**，并记审计 `幂等偏了`。
- 口径变更须另开新版幂等册并注明迁移；本册生效日当天不得改口。
